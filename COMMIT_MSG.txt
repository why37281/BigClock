refactor(rust): 改用 windows-sys 官方绑定，去掉手写 FFI 与跨 crate 句柄转换

编译前逐项核对的加固，目标是减少首次 cargo build 的报错面。

- 新增 win.rs：显示器枚举 / 找本进程窗口 / 定位 / 无边框 / 光标，
  全部走 windows-sys 的 RECT、POINT、HWND，不再手写 extern "system"。
  手写声明的风险是结构体 ABI 有出入时编译器不报错、运行时读到垃圾数据。
- 窗口句柄改为按【进程号】自己枚举查找，不再经过 tauri 的 hwnd()。
  这样全程只有 windows-sys 一套类型，不用在 windows / windows-sys
  之间转换 HWND（NonNull<c_void> 还是 *mut c_void 各版本并不一致）。
  顺带修掉"把裸指针存进 tauri State"这个必然的 Send/Sync 报错。
- 修 main.rs 确认的借用错误：watcher 闭包与后面代码同时使用同一个
  AppHandle 绑定，改为各处 clone。
- 重新从磁盘读取配置的逻辑抽成 reload_from_disk()，避免闭包里层层嵌套。
- Cargo.toml 增加 windows-sys 0.61（Win32_Foundation / Graphics /
  Graphics_Gdi / UI_WindowsAndMessaging / System_Threading）。

fix(front): 字体路径修正 —— 之前会 404

- 字体移到 src/fonts/ 并从 CSS 用相对路径引用后，@font-face 的 url
  仍指向已删除的 public/fonts/，构建时 Vite 报"didn't resolve"并原样保留，
  运行时会 404 悄悄回退到系统字体。
- 现已在构建期改写成 assets/ 下的真实哈希文件名，dist 里字体只有一份。
- 新增字体验收脚本：用 canvas 与 span 双重量字形固有宽度证明
  Rajdhani 真正生效（204.3 vs 回退字体 268.5）。
  （不能用 .clock 宽度判断 —— 它的格宽是写死的 em，换字体不换布局宽度。）

验证：前端 65 项检查仍全通过；字体加载与生效经无头浏览器实测确认。
